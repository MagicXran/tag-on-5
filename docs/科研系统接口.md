# 科研系统接入 OA 流程说明

## 1. 接入目标

本次 OA 接入的目标，是把科研系统整理后的三类数据同步到 OA 表单中，形成 OA 侧可查询、可流转、可留痕的数据档案。

当前涉及三类数据：

| 数据类别 | OA 中的业务含义 | 同步特点 |
|---|---|---|
| 科研合同(科研系统) | 合同档案 | 一条合同可能按经费号拆成多条 OA 记录 |
| 经费到账(科研系统) | 到账记录 | 每笔到账都按新增记录处理 |
| 经费收支(财务系统) | 经费收支档案 | 一个经费卡号对应一张主表和多条收支明细 |

系统整体不是直接把 Excel 原样推给 OA，而是先做本地清洗、拆分、补充、落库，再调用 OA 接口同步。这样做的好处是可以留下本地处理痕迹，也能保存 OA 返回的记录 ID，后续更新时有依据。

## 2.  ==整体流程==

```text
准备 OA 表单和权限
  -> 取得接口账号、登录人、rightId ★
  -> 读取 Excel 数据
  -> 清洗和转换数据
  -> 按业务规则拆分或补充数据
  -> 保存到本地数据库
  -> 判断本次是新增还是更新
  -> 调用 OA 批量接口 ★
  -> 读取 OA 返回结果
  -> 回写 OA 记录 ID
  -> 查看日志和核对 OA 页面结果
```

关键点是：本地数据库中的 `updateid` 是系统后续判断 OA 更新的核心凭据。首次新增成功后，必须把 OA 返回的记录 ID 保存下来；否则下一次同步可能无法正确更新，只能重复新增或人工修复。

## 3. ==接入前准备: 注意点==

### 3.1 OA 侧准备

OA 侧需要提前准备好三类表单：

| 数据类别 | 表单类型 |
|---|---|
| 科研合同 | 普通主表 |
| 经费到账 | 普通主表**(财务系统导出)** |
| 经费收支 | 主从表，主表保存经费卡号和汇总信息，子表保存明细流水**(财务系统导出)** |

每个表单都需要确认：

1. 表单编码是否固定。
2. 主表和子表的数据库表名是否固定。
3. 当前账号是否有新增和更新权限。
4. `rightId` 是否对应正确视图和操作权限 。 参考 [获取rightId.docx](#./获取rightId.docx)

### 3.2 接口账号准备

当前系统通过 OA REST 接口获取 token，再用 token 调用批量导入接口。

| 项目 | 需要确认 |
|---|---|
| REST 账号 | 是否为专用接口账号，是否长期有效 |
| REST 密码 | 是否会定期更换，如何安全配置 |
| 登录人 | 数据写入 OA 时显示为哪个用户 |
| token 有效期 | 过期后是否重新获取即可 |

## 4. 三类数据的同步流程

### 4.1 科研合同同步流程

合同数据的处理流程是：

```text
读取合同 Excel
  -> 清洗字段类型
  -> 清洗经费卡号
  -> 按经费号拆分记录
  -> 过滤无合同编号的数据
  -> 保存到本地合同表
  -> 区分新增和更新
  -> 同步到 OA 合同档案表
  -> 回写 OA 记录 ID
```

这里最重要的业务点是“一个合同可能有多个经费号”。系统会把多个经费号拆成多条记录，每条记录只保留一个经费号。这样 OA 侧看到的是多条合同档案记录，而不是一条记录里塞多个经费号。

注意点：

1. 拆分后，同一个合同编号可能对应多条记录。
2. OA 回写 ID 时必须能区分“合同编号 + 经费号”，否则不同经费号的记录可能互相覆盖。
3. 当前代码里部门匹配能力存在，但主流程没有启用，所以部门字段可能为空。
4. 当前实际筛选比较宽，只过滤合同编号为空的数据；是否还要按单位或经费号前缀过滤，需要业务方确认。

### 4.2 经费到账同步流程

经费到账的处理流程是：

```text
读取经费到账 Excel
  -> 清洗字段类型
  -> 过滤关键字段为空的数据
  -> 为每条记录生成单据号
  -> 保存到本地经费到账表
  -> 按新增记录同步到 OA
  -> 回写 OA 记录 ID
```

经费到账当前采用“永远新增”的策略。也就是说，同一份 Excel 如果重复导入，系统会生成新的单据号，并再次向 OA 新增记录。

注意点：

1. 单据号是本地系统生成的唯一标识，用来区分每一笔到账。
2. 当前设计不把经费到账当作“更新已有记录”，而是每次作为新的到账记录。
3. 重复导入是否允许，需要业务确认。如果业务不允许重复，需要增加导入批次或原始单据去重规则。
4. 当前关键字段过滤以经费账号、拨款时间、项目编号为主；入账金额是否必须非空，需要确认。

### 4.3 经费收支同步流程

经费收支的处理流程是：

```text
读取收支明细 Excel
  -> 从表头解析经费卡号和项目名称
  -> 读取明细流水
  -> 读取期初余额、累计发生额、期末余额
  -> 保存到本地收支明细表
  -> 按经费卡号分组
  -> 判断该经费卡号在 OA 是否已有记录
  -> 新增或更新 OA 主从表
  -> 回写经费卡号对应的 OA 主表 ID
```

经费收支是主从表结构：主表表达“某个经费卡号的整体收支档案”，子表表达“这个经费卡号下面的每一条收支明细”。

注意点：

1. OA 侧更新判断是按经费卡号来做的，不是按每条收支明细来做的。
2. 首次同步成功后，同一个经费卡号下的本地明细会共享一个 OA 主表 ID。
3. 再次同步时，系统会更新主表，并处理子表明细；但 OA 对子表是追加、覆盖还是合并，需要和 OA 方确认。
4. 如果某个经费卡号没有明细但有余额数据，系统会生成一条占位记录，只同步主表，不同步子表。
5. 收支明细的项目编号目前从经费到账数据里按经费卡号反查，查不到则为空。

## 5. 新增和更新的判断原则

当前系统的判断原则如下：

| 数据类别 | 新增/更新依据 | 当前行为 |
|---|---|---|
| 科研合同 | 本地是否已有相同合同和经费号记录 | 有则更新，没有则新增 |
| 经费到账 | 系统生成的单据号 | 永远新增 |
| 经费收支 | 本地该经费卡号是否已有 OA 主表 ID | 有则更新，没有则新增 |

注意点：

1. OA 返回的记录 ID 必须可靠保存。
2. 本地数据和 OA 数据的唯一性规则必须一致，否则会出现重复新增或错误更新。
3. 如果 OA 数据被人工删除，而本地还保留旧 ID，再次更新可能失败。
4. 如果本地数据库丢失，系统将无法知道哪些 OA 记录曾经同步过。
